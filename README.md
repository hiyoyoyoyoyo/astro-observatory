# 星象台 · Astro Observatory

> 一本书 = 一片星象，书里每个可执行的方法 = 一颗星子。
> 装备几颗，就能就着你手上的真实问题让它们开口——**先各自表态，再互相质询，最后收成一个结论。**

一个 Windows 本地应用。把你的书拆成可以随时调用的「能力」，遇到问题的时候挑几颗放上桌，让它们分头作答，每句结论都能点回原文核对。

**开源 · 免费 · 数据不出本机 · 自备模型 API Key**

## 它解决什么问题

你读过不少书，划线、做笔记、存进收藏夹，然后就再也没打开过。真遇到事的时候，一本都想不起来。

问题不在记性。**书是线性的，你的麻烦是零碎的。** 你没法用目录去索引一个具体的、还带着情绪的处境。

星象台不给你写摘要。它把书拆成十几颗「星子」，每颗都是一个可以直接用的方法：

- **触发情境** — 什么时候该请它出来
- **执行步骤** — 具体怎么做，能照着做
- **适用边界** — 什么时候不该用它

三样缺一样，它就只是个金句。

## 核心能力

### 1. 多星分头作答，不是一次回答切三段

遇到具体问题，挑 3 颗星放进席位，说出你的处境。它们按各自的逻辑**独立作答**，最后由主持星收束：

- 一致点在哪儿
- 分歧在哪儿，以及分歧的根源
- 下一步具体做什么
- **改判条件** — 什么情况下这个结论要推翻

### 2. 每句结论都点得回原文

回答旁边标着来源星子，点一下翻到那张卡，看到的是书里那一段，不是模型转述。**书里没有的它会明说「这一点书里没有」**，而不是把话说圆。

### 3. 谈完存档，下次接着谈

装备了哪几颗星、问过什么、结论是什么，都留着。下次打开还是那间会议室，不用从头复述背景。

### 4. 跨书融合

两本以上的书可以挑最相关的几颗星到同一张桌上，让不同作者的观点当面对质。

### 5. 四种问法

| 方式 | 说明 |
|---|---|
| 单星直答 | 只按一颗星的方法回答，最省 |
| 合议 | 每颗星各自答一遍，主持星收束 |
| 整本参议 | 从一本书里取 3 颗主星分头作答，在该书语境里收束 |
| 星象融合 | 跨书挑星，意见相左时当场质询 |

## 快速开始

### 方式一：下载安装包（推荐）

去 [Releases](../../releases) 下载 `astro-observatory-x.y.z-setup.exe`，双击安装。

> Windows 可能提示「已保护你的电脑」，点「更多信息 → 仍要运行」即可。这是因为安装包没有购买代码签名证书，
> 并非程序有问题；不放心可以把文件传到 [virustotal.com](https://www.virustotal.com) 自行扫描。

### 方式二：从源码运行

```bash
git clone https://github.com/<your-name>/astro-observatory.git
cd astro-observatory
npm install
npm start          # 开发模式，Electron 直接起
```

也可以不起 Electron，直接用浏览器打开 `index.html`——前端是纯静态的，零构建、零 CDN。
（浏览器的 `file://` 会有 CORS 限制，下载书和调模型建议走桌面版。）

## 第一次用要做的三步

1. **接一个模型** — 设置里填任意 **OpenAI 兼容**接口的 Base URL / 模型名 / API Key。
   内置 DeepSeek、Kimi、通义、智谱、硅基流动、Ollama 六个预设。
2. **导入一本书** — 支持 `epub` / `docx` / `md` / `txt`。星册里已经放了一本公版的《孙子兵法》可以先试手。
3. **装备星子，开一场星议** — 挑 3 颗星入席，把正在卡住的事说出来。

### 关于 API Key

软件本身**不含模型费用**，这是刻意的设计：

- 用哪家、换哪家、花多少钱，都由你决定
- Key 只存在你自己的电脑上，不经过任何服务器
- 接本地 Ollama 时可以完全断网使用

**注意**：目前 Key 以明文存在浏览器的 `localStorage` 里，这是已知的待改进项（见 [Issues](../../issues)）。
如果这台电脑有多人共用，建议把 Key 的存储方式选成「仅本次会话」。

## 书会被上传吗

不会。书稿、能力卡、对话记录全部存在本机。

只有**蒸馏和对话时抽取的片段**会发给你自己配置的那个模型服务——数据发给的是它，不是这个项目的作者。用 Ollama 时连这一步都在本机完成。

## 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 JS / CSS / SVG | 零构建、零依赖、`file://` 直接能跑，改一行就能看效果 |
| 桌面 | Electron 33 | 主进程代理 HTTP 请求，绕开 `file://` 的 CORS 限制 |
| 数据 | JSON + localStorage | 人类可读，用户能自己备份和迁移 |
| 模型 | 任意 OpenAI 兼容接口 | 只维护一条通道；BYOK，不用替用户垫推理费 |

代码分模块很小，主要几个：

```
index.html      界面骨架
styles.css      全部样式（深色主题，无 CSS 框架）
stars.js        状态、索引、装备、存档
llm.js          模型通道（桌面走 IPC，浏览器走 fetch）
distill.js      文件 → 取样 → 四阶段蒸馏 → 能力卡
podium.js       提示词构造、多星编排、消息渲染、引用
app.js          视图控制器（星盘 / 星册 / 星象台 / 融合）
desktop/main.js 窗口 + 请求代理
```

更细的模块职责、数据结构、踩坑记录见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 术语

界面里用的是天文词汇，不是产品黑话，对照一下：

| 界面词 | 实际含义 |
|---|---|
| 星象 | 一本被蒸馏过的书 |
| 星子 | 书里蒸馏出的一个能力 |
| 主星 / 卫星 | 能独立召唤的 / 只负责路由的 |
| 星等 | 由重要度推出的亮度，1.0 最亮（自造排序指标） |
| 星轨 | 星子之间「谁从谁派生」的连线 |
| 星盘 / 星册 | 单本书的星图 / 全部书的总目录 |
| 星象台 | 带真实问题来对话的地方 |
| 星议 | 一次对话存档 |

## 它做不到什么

写在前面，省得你装了才发现：

- **不能替你读书。** 它整理结构，理解还得你自己来。
- **不写摘要。** 要摘要的话通用 AI 做得更好。
- **PDF 要转格式。** 扫描版不行，它要的是文字不是图片。
- **只有 Windows。** macOS 和 Linux 没打包，理论上能跑起来但没验证。
- **蒸馏要几分钟。** 不是三秒出奇迹，慢是因为它真的在逐章取原文。
- **只内置一本公版书。** 版权书请自己导入，内容责任在你自己。
